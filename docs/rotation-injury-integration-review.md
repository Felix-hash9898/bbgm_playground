## 系统模型与修改理由

健康计划 → 可用性 → 自动伤病计划 → 有效Current Override条件再平衡 → 原Dynamic GameSim → 真实阵容/分钟/体力/伤病 → 赛后生产统计/未来状态。

OVR是单一评级回归，不是实际贡献的万能指标；GameSim还使用真实composites、usage、synergy、valueNoPot、疲劳和分钟debt。用户规划继续只用允许的fuzzed评级/百分位/角色信号。No Ratings规划只使用公开顺序/位置、用户分钟和中性耐力；真实composites只在GameSim内部使用。No Ratings Custom测试中的健康分钟是冻结的显式用户输入，不是运行时从隐藏评级重新生成。

原main把base=0与base>0分池，按健康分钟排名领取晋升slot/容量；Low Core reserveShare、RoleFit容量和fallback叠加造成不合理的末端负担。已有自动候选使用健康分钟连续承诺、既有Auto参考、同一可用池、共享容量阶段和按剩余headroom软化偏好；本轮继承这些改动，不回退到C5或V1.5。

本轮跨阶段根因：旧Override helper再次按automatic>EPSILON分active/inactive，使用另一套逐人promotion优先级；极小的自动目标变化会改变谁吸收整批pin留下的分钟。伤病角色需求也未计入pin主动让出的健康分钟。Lock减少可调对象，放大变化。

### 最终修复

1. 把context、数值、可用性、保护上限、pin总额的验证提取为 `getCurrentMinutesOverridePins`。
2. 以原自动计划作为条件基准，固定有效pins，只处理实际差额。pin到自动目标必须对其余人完全无影响。
3. Override复用同一分配器和容量/Auto/角色模型，不再建立active/inactive/promotion队列。reference保留pinned球员，分配候选排除pinned和受保护球员，避免pin元数据本身改变参考名单。
4. 角色缺口计入伤病及pin相对健康目标的变化。保留用户保护hard cap，自动ordinary/extended偏好仅在必要时软化。
5. 向上pin先扣临时伤病extra，再按比例减少健康底线。weights=caps时使用精确比例解，避免把各自小于epsilon的合法extra丢掉后抛错。
6. 健康Custom、Save schema、API生产实现、原GameSim/换人/伤病/球权逻辑不改。loadTeams、Roster preview和共享校验统一传入已有playoffs标志。
